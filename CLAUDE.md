# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`oblivlib` is a Python library implementing classic oblivious algorithms — Oblivious RAM (ORAM) and Oblivious Map (OMAP). It targets a client/server deployment where the client is trusted and may compute non-obliviously, while the server only stores encrypted data and answers batched read/write queries. The library backs the maintainers' publications (notably "Towards Practical Oblivious Map", VLDB 2025). See `README.md` for the paper-to-file mapping of each algorithm.

The whole package is type-clean. basedpyright reads `pyrightconfig.json` and must be pointed at the env where the deps are installed (via `--pythonpath` or your editor's interpreter selection); otherwise every third-party import fails to resolve and cascades into spurious errors.

CI (`.github/workflows/ci.yml`) installs `.[dev]` and runs `ruff check`, `ruff format --check`, `basedpyright`, and `pytest` on push/PR to `main`.

## Architecture

### Client/server split
All ORAM/OMAP constructions talk to storage only through a `Client` (`src/oblivlib/dependency/client.py`), passed in their config as `client=` — they never touch storage directly. The layers below it:
- `StorageServer` (`storage_server.py`) is the storage engine: it answers the protocol messages of `protocol.py` and has no transport of its own. Trees live in fixed-row stores (memory, or files under its `storage_dir`) or, for plaintext debugging, variable-row memory stores (`server_stores.py`).
- A `Backend` carries messages: `LocalBackend` calls the server in process (rows are immutable bytes, so nothing is copied); `TransportBackend` encodes them for a byte-level `Transport` (`transport.py`: `ZmqTransport`, `LoopbackTransport`, `SimulatedNetwork`; the server side is `serve(ZmqListener(...), server)`).
- `Client.local(storage_dir=None)` and `Client.connect(endpoint)` build the two usual stacks. Swapping local for remote is transparent to the algorithm code.

Construct a scheme with a `client`, call `init_server_storage(...)` (the client builds the tree locally and hosts it), then issue operations. The wire messages are defined in `protocol.py`.

### Query batching model
Operations do not perform I/O immediately. A construction stages queries on the client via `add_read_path` / `add_write_path` / `add_read_list` / `add_write_list` (each keyed by a string `label`), then calls `client.execute()`, which sends one batch whose **writes apply before its reads** and returns an `ExecuteResult`; schemes read a result via `result.require(label)`. A failed batch raises the server's error, mapped to its class in `errors.py`. Path rows travel as `PathRows` (`{heap_index: row}`, `b""` = absent node) and the scheme's `PathCipher` turns them into buckets. By default the client **defers writes**: an `execute()` that stages only writes sends nothing, and its writes ride on the next batch — the access sequence is unchanged and the round count halves; `flush()` and `close()` send them. `client.metrics` reports rounds, payload bytes, and wire bytes. One `Client` per thread. Every config requires `client=`, and its `name` (the storage label) defaults to the scheme's prefix plus a random hex suffix (`config.unique_name`), so schemes sharing one client never collide; pass `name=` only to address storage by a known label.

### Storage and data types
- The data contract is bytes: ORAM keys are int addresses in `[0, num_data)`, OMAP keys are `bytes` of at most `key_size`, values are `bytes` of at most `data_size`. `contract.py` checks it at every public entry point and raises `ContractError` before any state changes. The library never pickles.
- Core data classes and type aliases live in `src/oblivlib/dependency/types.py`: `Data` (a block: `key`, `leaf`, `value`, whose field order — the `FieldTuple` mixin it shares with `AVLData`/`BPlusData` — is the stored format), `PathData`/`PathRows`, the `ListOp` list-write ops, and the `UNSET` sentinel that distinguishes "read" from "write" in `operate_on_key`.
- Every stored record has a fixed layout built from `layout.py` fields (`UInt`, `Bytes`, `FixedBytes`, `Optional`, `Array`, `Seq`, `Record`, `Variant`; counters use `BitFields`). A scheme declares `_key_field` / `_leaf_field` / `_value_field` on `TreeStorageBase`, which builds `_block_layout`; a bucket is `Seq(block, bucket_size)` and a sealed row is `ciphertext_length` of that size, computed, never estimated. A value that does not fit its field raises `CapacityError` where it is encoded. B+ block ids are `UInt(64)`; `gc_length >= MIN_GC_LENGTH` (64). A `PathCipher` (`path_cipher.py`) encodes each bucket and, when encrypted, seals it into one fixed-length row.
- `build_tree` (`tree_builder.py`) builds the initial tree on the client, in memory or in an encrypted `build_file`; `Client.host_tree` hands it to the server (adopt, attach, or stream). Every scheme builds through `TreeStorageBase._build_tree`. Heap-index math (`compute_level`, `path_indices`, `leaf_lca`, `fill_data_to_path`, ...) lives in `heap_index.py`.

### ORAM layer (`src/oblivlib/oram/`)
Every scheme is constructed from a single frozen, keyword-only **config object** (defaults centralized in `src/oblivlib/dependency/config.py`), e.g. `PathOram(PathOramConfig(num_data=.., data_size=.., client=..))`; the config hierarchy mirrors the scheme hierarchy (`OramConfig` → `Da/Freecursive/Recursive/MulPath...Config`, `OmapConfig` adds `key_size`). Configs validate in `__post_init__`. `TreeBaseOram` (`tree_base_oram.py`) is the abstract base for all tree-based ORAMs; it and the OMAP `OstBaseOmap` both inherit `TreeStorageBase` (`src/oblivlib/dependency/tree_storage_base.py`), which owns the shared config accessors, leaf math, stash, and path encryption/decryption. `TreeBaseOram` adds stash eviction and one access template: each scheme implements the single hook `_operate_on_key_without_eviction` (find the leaves, then `_read_block`), and `_write_back` evicts the pending paths; `operate_on_key` is the hook plus `_write_back`, and `eviction_with_update_stash(key, value)` sets the value in the stash, then calls `_write_back` (it always executes; write deferral holds the write-only batch). Each scheme also implements `init_server_storage(data=...)` (a mapping or a one-shot stream of `(key, value)` pairs). The position map lives on the schemes that keep one (`PathOram` and its subclasses except `StaticOram`, `RecursivePathOram`); `TreeBaseOram` is generic over its position-map level type, and a recursive scheme's `_levels` (smallest first) are `TreeStorageBase` level objects, not ORAMs. The key public operation is `operate_on_key(key, value=UNSET)` — always returns the current value (`b""` until written), and writes `value` if one is provided. Concrete schemes: `PathOram`, `RecursivePathOram`, `FreecursiveOram` (insecure with `reset_method="hard"`, secure with `"prob"`), `DAOram`, `MulPathOram`, `StaticOram`. DA and Freecursive share their non-counter machinery (PRF leaves, levels, hosting) through `oram/counter_oram.py`; every path read goes through `TreeStorageBase._open_paths` / `_read_paths`, and `_write_paths()` writes back exactly the paths last read (a write-back that never happened is staged ahead of the next read, so no block is ever held twice).

### OMAP layer (`src/oblivlib/omap/`)
Two families:
- **Oblivious Search Tree (ODS)** maps, based on `OstBaseOmap` (`ost_base_omap.py`) — an abstract base that, like `TreeBaseOram`, inherits `TreeStorageBase`, but maintains a `root`, `local`, and `stash`. It exposes `insert`, `search`, and `delete`, which check the contract and call each scheme's `_insert` / `_search` / `_delete`. Concrete: `AVLOmap` and `BPlusOmap`, configured by `AvlOmapConfig` / `BPlusOmapConfig` (both `TreeOmapConfig`). Each map has one descent: every fetch re-homes the node, and the op returns to the stash every node it no longer needs (search holds none). Every op is per-op oblivious: it pads to its budget of path accesses (one path per round) with dummy read+evict accesses; see "Access budgets" below.
- **Composed maps**: `OramOstOmap` (`oram_ost_omap.py`) is the VLDB 2025 framework — it combines *any* `TreeBaseOram` with *any* `OstBaseOmap`, hashing keys via a PRF into the ORAM, which stores each slot's root encoded with the ODS's `root_layout` (size its `data_size` with `OramOstOmap.oram_data_size(ost)`); it supports `search`, `insert`, and `delete`. `GroupOmap` uses a group-by-hash design with an upper ORAM for metadata and a `MulPathOram` lower ORAM whose blocks are named by the user's key.

### Crypto (`src/oblivlib/dependency/crypto.py`)
`Encryptor` is the abstract encryption interface (`AesGcm` is the AES-GCM implementation; `ciphertext_length` must be exact), alongside `PseudoRandomPermutation` (`FeistelPrp`) and PRF (`Blake2Prf`) primitives, and the key-hashing module functions `hash_data_to_leaf`, `hash_data_to_map` used by the composed maps. Constructions take an `encryptor` in their config; when `None`, buckets are stored as plaintext encoded rows (memory servers only) — useful for debugging. Only the client holds the encryptor; the server only ever sees sealed rows. Buckets are encrypted as a unit (per-bucket ciphertext, fixed row length); GCM auth is defense-in-depth under the honest-but-curious model, not malicious-server integrity. A value-carrying scheme declares its fields instead of reimplementing path encryption.

## Access budgets (ODS maps)

Budgets count path accesses (one path read plus its write-back), independent of the client's write deferral. Every fetch re-homes the node (fresh leaf, stored in its parent before the read), and the op keeps in `local` only the nodes it may still change; every node it provably no longer needs goes back to the stash at once (`_return_local`) and rides on a later write-back, which are staged lazily (just before the next read, or at op end). Every block an op returns needs one eviction: `_return_to_stash` counts it, each staged write-back pays one, and `_pad_to` raises unless the padding accesses cover the rest. An op pads to `a*h + b` (`TreeOmapConfig.budget(op)`, default `MIN_BUDGETS`; overrides may only raise them); hidden mode (`distinguishable=False`) pads every op to the largest. `TEXTBOOK_BUDGETS` / `Config.textbook(...)` give the original held-node implementation's counts, clamped to the minimum where it padded less. Pinned by `test_every_op_spends_exactly_its_budget`, the witness tests in `tests/omap/test_avl_omap.py` / `test_bplus_omap.py`, `TestOmapStash`, and the config table.

- AVL `h = avl_max_height(n)`: largest `H` with `N(H) <= n`, `N(1)=1, N(2)=2, N(H)=N(H-1)+N(H-2)+1`. Tight.
- AVL search `h`: each node goes back before the next read, so it rides on its own write-back. Tight.
- AVL insert `2h`: only the deepest node with nonzero balance can rotate, so nodes above its parent are returned as soon as it is seen; with none, all `h` path nodes and the new leaf return at the end and the last write-back carries one. Tight (a root over a spine of balanced nodes).
- AVL delete `2h`: `p` path fetches plus at most two per rotating node; each path node's finished subtree returns as soon as it is rebalanced, so every rotation fetch above the lowest one pays for a returned block. With `(p - 1) + r <= h - 1` (a rotating node's path child is two levels lower) the cost is at most `2(p + r) <= 2h`; a miss costs `2h - 1`. Tight (a double-rotation chain up a mirrored Fibonacci tree).
- B+ `h = bplus_max_levels(n, order)`: height grows only by a root split, which needs a full root-to-leaf path with every other subtree minimal: `F(1) = order`, `F(k) = F(k-1) + (order - 1)(ceil(order/2) - 1) ceil(order/2)^(k-2)`; `h` is the largest `L` with `F(L-1) <= n`. Tight for odd orders; even orders tight at 3 levels, unproven deeper.
- B+ search `h`: streamed like AVL. Insert `3h - 2`: a node that is not full cannot split, so its ancestors return at once; on a full path, `L` path nodes plus one new node per split and a new root return at the end (a root split forces `L <= h - 1`). Delete `4h - 3`: the root, then child and sibling per level; a child above the minimum cannot underflow, so everything above it returns at once; on a minimal path all `2L - 1` return at the end. Both tight for odd orders.
- Textbook preset (the original code's normal-path counts): AVL search `3h + 1`, insert `3h`, delete `3h + 2`; B+ search `2h`, insert `3h` (the original's `2h` is below the minimum; its dummy-op `3h`), delete `4h - 3` (the original's `3h` is below the minimum).

## Conventions

- All public/shared methods on base classes use single-underscore (not name-mangled `__`) names so subclasses can access them — this is intentional.
- Public names are re-exported from `oblivlib.dependency`; its `__all__` is the authoritative list (`python -c "import oblivlib.dependency as d; print(d.__all__)"`). Import those from the package (`from oblivlib.dependency import Client, Data, ...`). Internal machinery is deliberately not re-exported and is imported from its submodule: `protocol` (the wire messages), `contract`, `heap_index`, `layout`, `load_bound`, `path_cipher`, `server_stores`, `tree_storage_base`, `flexible_binary_tree`, and the `Bucket` type in `types`. (`config` names are re-exported, but scheme modules also import them from `oblivlib.dependency.config`.)
- `demo/` contains runnable client/server examples over ZeroMQ (`server.py` and `client.py`, which runs an ORAM and an OMAP over one connection) — the canonical reference for remote deployment.
- **No comments** in source or tests (tool pragmas like `# noqa` excepted). Names and types carry the meaning; any rationale the code cannot express — security arguments, invariants, format gotchas, round-count derivations — goes in this file or the commit/PR description, not inline. Docstrings that restate a signature are dropped.
- Invariants and where they are pinned: no block held twice across a scheme's trees, stashes, and ODS `local` (`duplicate_blocks` in `tests/conftest.py`, asserted by the model tests); row size equals the declared layout for every scheme (`test_row_size_is_the_declared_block_layout_of_every_tree` and the OMAP twin); out-of-range fields raise `CapacityError` (`tests/dependency/test_layout.py`, GC overflow in `tests/oram/test_oram_edge_cases.py`).
- A trivial helper already exercised by a higher-level test need not have its own dedicated test; tests order their methods to mirror the source function order — add a test next to the sibling of the source function it exercises, not at the end of the file.
